## Three views of a text

The same text is measured with three different numbers:

```rust
fn main() {
    let word = "çay";
    println!("{}", word.len());
    println!("{}", word.chars().count());
    println!("{:?}", word.bytes().collect::<Vec<u8>>());
    println!("{:?}", word.chars().collect::<Vec<char>>());
}
```

```text
4
3
[195, 167, 97, 121]
['ç', 'a', 'y']
```

| View | Method | When |
|---|---|---|
| Bytes | `.bytes()`, `.len()` | Files, networks, size calculations |
| Characters | `.chars()` | Letter operations |
| Visual letters | Not in the standard library | The unit you see on screen |

A `char` is not always one "visual letter". Some emoji and accented letters are made of several `char`s.

## Taking a part safely

If the boundary may fall in the middle of a letter, use `.get`. It gives `None` rather than panicking:

```rust
fn main() {
    let word = "çay";
    println!("{:?}", word.get(0..1));
    println!("{:?}", word.get(0..2));
}
```

```text
None
Some("ç")
```

`{:?}` writes `Some("...")` or `None`. We will see the `Option` type in section eleven.

To take by character position:

```rust
fn main() {
    let word = "şekerleme";
    let first_three: String = word.chars().take(3).collect();
    println!("{first_three}");
    println!("{:?}", word.chars().nth(1));
}
```

```text
şek
Some('e')
```

## Case and Turkish

`to_uppercase` applies Unicode rules but knows no language: `"i".to_uppercase()` always gives `I`, not the Turkish `İ`. Rust's standard library has no language-aware conversion.

## Why so much trouble?

Rust guarantees that text is always valid UTF-8 and does not lie to you. Many languages hide the same problems silently; those programs break on Turkish names. That is why in this
section's exercises we learn to think of text work through `.chars()`.
