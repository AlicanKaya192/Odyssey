With this module, the four modules of the **Cyber Security with Python**
path are complete: Security Fundamentals, Cryptography, Network and Web
Security, System Security and Operations. This note describes where you can
go from here.

## What this path was, and was not

This path was **not a penetration testing (pentest) course.** It taught
defence and concepts with Python: why a vulnerability arises, how it is
noticed, how it is prevented and what is done when it happens. All the
examples were self-contained toy programs; none of them connected to a real
system or changed a real setting.

This knowledge is the foundation of every security job: a defence team,
someone developing secure software, an incident responder or a system
administrator all work with the same concepts.

## If you want to learn the attacking side

Penetration testing is a separate profession, and there are legal ways to
learn it:

- **Your own lab:** working on your own computer, in virtual machines you
  set up yourself, with training systems deliberately left vulnerable. You
  break and rebuild; you harm no one.
- **Authorised competitions and training environments (CTF):** environments
  whose targets are explicitly given and whose rules are written.
  Permission covers only the targets the rules name.
- **Bug bounty programmes:** only within the scope the programme writes and
  under its rules.

Whichever you choose, the line from the Ethics and Law section does not
change: **no system is touched without written permission**, nobody goes
beyond the scope, and data seen during a test is protected. As a
profession, every penetration testing job runs with a contract, a scope
document and a report.

## Continuing in Odyssey

- **CI/CD and DevOps**, **MLOps and ML System Design:** secrets management, dependency checks
  and the release gate are what you saw here, in an automated pipeline.
- **Docker:** the container counterpart of process isolation and least
  privilege (a non-root user, a small image).
- **Writing REST APIs with FastAPI:** applying authentication, input validation and error
  handling in a real web service.

## Keep learning

- Read security advisories and post-incident reports: real incidents keep
  repeating the very mistakes described here.
- Add this module's checks to your own projects: secret scanning, pinned
  versions, structured logs, restore tests.
- Pick an area and go deep: secure software, incident response, digital
  forensics, cloud security or privacy engineering.
